## 一、通用规格

### 1.1 双尺寸支持

| 参数               | 64×64 版                     | 128×128 版                       |
| ---------------- | --------------------------- | ------------------------------- |
| 单帧分辨率            | 64×64 px                    | 128×128 px                      |
| 在网页版 prompt 中描述为 | "在 512×512 画布中绘制 64×64 像素画" | "在 1024×1024 画布中绘制 128×128 像素画" |
| 后处理缩放            | 512px 缩到 64px (8:1)         | 1024px 缩到 128px (8:1)           |
| Aseprite 拼合列宽    | 512px (8列 × 64px)           | 1024px (8列 × 128px)             |

### 1.2 共享规格

- **背景**: 透明 PNG
- **色彩**: 16~32 色调色板，平涂无渐变
- **风格**: 像素画，锐利边缘，无抗锯齿，无羽化
- **输出流程**: 网页生成 → 下载 PNG → rembg 去背景 → 裁切/缩放 → Aseprite 拼合

## 二、网页版操作核心要领

### 2.1 同一个对话，不要开新对话

网页版 Gemini 自动保持对话上下文。**同一个对话里连续发的每条消息，模型都会记得之前的内容**。这就是免费的 Chat Session。

```
❌ 错误：每帧都开新对话 → 模型每帧从头理解角色 → 帧间不一致
✅ 正确：首帧开始后一直在这个对话里发 → 模型记住角色设计
```

### 2.2 下载 → 上传 → 编辑 循环

网页版没有"代码传图"功能，但你可以**手动下载再上传**：

```
消息1: 上传角色参考图 + prompt → 生成 idle_f1
         ↓ 点击下载 idle_f1
消息2: 上传 idle_f1 图片 + "保持这张图不变，只把身体上移..."
         ↓ 点击下载 idle_f2
消息3: 上传 idle_f2 + "把身体移回地面..."
         ↓ 重复
```

### 2.3 编辑模式的核心话术

网页版 prompt 的开头必须明确告诉 Gemini"改这张图，不是画新的"：

```
❌ 错误（新画模式）：
"猫娘正面全身像素画角色：身体前倾5度..."

✅ 正确（编辑模式）：
"这是猫娘待机帧1。请保持图中角色所有细节完全不变——
发型、五官、服装颜色、猫耳形状、尾巴、身体比例都不要动。
只做以下调整：将整个身体垂直上移一点，脚略微离地，胸腔稍微膨胀。
这是呼吸的吸气帧。其他部分保持与上传图片完全一致。"
```

## 三、每条消息的通用前缀

### 首帧发消息时（第一个消息）

```
像素画风格，在512×512画布中绘制一个64×64像素画猫娘角色，
PNG，纯绿色背景 #00FF00 (RGB 0, 255, 0)，16~32色调色板，边缘锐利，无抗锯齿，无羽化，
居中对齐，无描边，无签名，无水印。

角色设计锚定：严格保留参考图中猫娘的猫耳形状(三角形)、尾巴
(蓬松弯曲)、服装配色(主色+副色)与身体比例(Q版2~2.5头身)，
仅根据动作描述改变肢体姿态与表情。

[动作描述...]

角色居中于画布中央，四周留透明背景，像素块清晰可辨。另外请给角色加2-3PX白色描边。
```

> 如果选 128×128 版，把"512×512"改成"1024×1024"，"64×64"改成"128×128"

### 后续帧（编辑模式）

同一对话中，继续发消息，上传上一帧图片，然后写：

```
这是上一帧生成的结果。请保持图中角色所有细节完全不变——
发型、五官、服装颜色、猫耳形状、尾巴、身体比例全部不要动。

只做以下一处调整：[描述这一帧要变的唯一内容]

其他部分保持与上传图片完全一致。
```

## 四、逐帧 prompt（网页版操作步骤）

> **操作说明**: 下面每 Row 标注的"共 X 帧"是这个动画的总帧数。

## 五、网页版生成工作流

### 操作步骤图

```
打开 gemini.google.com
    ↓
新建一个对话
    ↓
上传角色参考图 + 写首帧 prompt → 生成 → 下载 PNG
    ↓
在同一对话中，上传上一帧的 PNG
    ↓
写编辑式 prompt → 生成 → 下载 PNG
    ↓ (重复 上传→编辑→下载 循环)
所有帧生成完毕
    ↓
后处理（rembg → 裁切/缩放 → Aseprite 拼合）
```

### 每行动画的对话策略

| 策略           | 说明                      |
| ------------ | ----------------------- |
| **每行动画一个对话** | 避免动作描述互相干扰              |
| **首帧精修再继续**  | 首帧不满意就重发，满意了再往下         |
| **如果某帧崩了**   | 在同一对话中发"重做上一帧，[改述你的要求]" |
| **如果严重走形**   | 回到首帧重新开始，或新开对话          |

### 后处理流程

```
下载的 PNG（含背景）
    ↓
rembg 移除背景
    ↓
裁切 + 缩放到最终帧尺寸（64×64 或 128×128）
    ↓
Aseprite 拼合 spritesheet
   ├─ 64×64版: 512px宽 × (64×N)px高
   ├─ 128×128版: 1024px宽 × (128×N)px高
   ├─ 每行8帧排列
   └─ 导出 pet_spritesheet.png + pet_spritesheet.json
```

### 参考图锚定使用说明

1. 选一张最有代表性的猫娘全身图作为参考图
2. 首帧 idle_f1 上传参考图，验证生成结果
3. 后续每帧上传**上一帧的生成结果**，形成链式锚定
4. 如果某帧崩了：在同一对话中重发该帧，调整措辞
