# 窗口动态缩放实现记录

## 目标
让 hover 工具栏完整显示在桌宠上方，不被透明窗口的 `overflow: hidden` 裁剪。

---

## 探索过程

### 1. CSS 方案（失败）
尝试用 `top: -52px` 让工具栏上浮到宠物头顶，配合 `overflow: visible`。但 Windows 窗口管理器裁剪了超出窗口边界的内容，即使 CSS `overflow: visible`，工具栏仍然不可见。

### 2. Tauri setSize 单独使用（失败）
Tauri `win.setSize()` API 正常工作（`innerSize` 日志证实 resize 执行了），但窗口向下扩展（Windows 窗口锚点是左上角），工具栏相对宠物的位置不变，仍然重叠。

### 3. 四周扩展方案（基本成功）
同时调用 `setPosition` + `setSize`，让窗口向四周扩展，以宠物为中心保持不动：
- 窗口从 220×220 → 400×400
- `newX = baseX - (400-220)/2`，`newY = baseY - (400-220)/2`
- 窗口左上角上移 90px、左移 90px
- 宠物在 flex 居中下保持 screen 坐标基本不变

## 最终方案核心逻辑

```typescript
// composables/useWindowResize.ts

// 只在第一次展开时捕获基准位置，避免每次重新获取导致漂移
if (!baseCaptured) {
  const pos = await win.outerPosition()
  baseX = pos.x; baseY = pos.y
  baseCaptured = true
}

// 尺寸变化时同步移动窗口，保持宠物位置不变
const newX = baseX - (width - ORIGINAL_WIDTH) / 2
const newY = baseY - (height - ORIGINAL_HEIGHT) / 2
await Promise.all([
  win.setSize(new PhysicalSize(width, height)),
  win.setPosition(new PhysicalPosition(newX, newY))
])

// 缩回原始尺寸后才重置基准，允许下次基于新位置扩展
if (width === ORIGINAL_WIDTH && height === ORIGINAL_HEIGHT) {
  baseCaptured = false
}
```

## 发现的关键问题

1. **Windows 窗口扩展方向**：默认向右下扩展（锚点左上角），需要同时 setPosition 才能四周扩展
2. **minWidth > 窗口宽度**：`tauri.conf.json` 中 `minWidth: 200` 比实际窗口 170 还大，会静默阻止所有 setSize 调用
3. **Logical vs Physical**：混用 LogicalPosition/PhysicalSize 可能导致亚像素偏移，最终采用 PhysicalPosition + PhysicalSize
4. **baseCaptured 释放时机**：必须在 resize 实际完成后才能重置，否则下次 expand 会基于缩回后的错误基准计算

## 存在问题

- 缩放时有短暂闪烁（缺少 transition 动画）

- 气泡聊天窗口的 resize 扩展尚未实现
- `overflow: visible` 在不同系统上的裁剪行为需进一步验证
