# Nano Banana 2 像素序列帧生成方法 · 网页版实践

> 基于 Google Gemini 网页版 + GitHub Cookbook 示例整理
> 2026-04-29

---

## 一、先理解 NB2 在网页版下怎么工作

Nano Banana 2 是 Gemini 的图像生成模型。你用网页版发消息时，后台就在用它。

| 网页版能做的事 | 网页版不能做的事 |
|--------------|----------------|
| ✅ 上传参考图 + 写 prompt 生成一张图 | ❌ 真正理解"像素坐标" |
| ✅ 同一对话中记住你之前的要求 | ❌ 精确执行"把第3行像素改色" |
| ✅ 基于上传的图片做局部修改 | ❌ 在限制色板上自动保持精准一致 |
| ✅ 连续对话保持角色概念 | ❌ 独立开新对话时记得之前的角色 |

### 核心结论

NB2 在网页版下是**概念设计机 + 参考图迭代器**。你要的是一个工作流利用它的编辑能力，而不是指望它一次出完美像素。

## 二、网页版两种生成方案

### 方案 A：双消息编辑法 ★ 推荐

**适用场景**: 需要精确控制的动画（idle 呼吸、表情微变）

核心就 2 步交替：

```
消息1: 上传图片 + "改一下XX" → 生成
        ↓ 下载结果
消息2: 上传结果 + "再改一下YY" → 生成
        ↓ 下载结果
...重复
```

关键规则：
- **整个动画在一个对话里** —— 不要每帧新开对话
- **每帧只改 1 个参数** —— "只把身体上移"而不是"身体上移+尾巴摆动+表情变开心"
- **用"保持不变，只做"句式** —— 告诉 Gemini 是"编辑"不是"新画"

### 方案 B：首帧锚定 + 独立帧（一次性生成多帧）

**适用场景**: 快速预览、动作差异大的帧（Walk、Spin）

```
上传角色参考图
    ↓
"请画5帧[动作]序列：帧1做X，帧2做Y，帧3做Z..."
    ↓
NB2 可能一次性生成一张包含多个子图的图片
    ↓
手动裁剪成单帧
```

这个方法效率高但帧间一致性较差，适合验证动作设计而非最终素材。

## 三、网页版编辑模式的正确"话术"

### 首帧（从参考图生成）

首帧需要上传角色参考图 + 完整的像素画规格描述：

```
在512×512画布中绘制一个64×64像素画[角色描述]。
像素画风格，16~32色调色板，PNG透明背景，
边缘锐利，无抗锯齿。居中对齐，无描边，无水印。

角色设计锚定：严格保留参考图中角色的猫耳形状、
尾巴、服装配色与身体比例(Q版2~2.5头身)，
仅根据动作描述改变肢体姿态。

[动作具体描述]

角色居中于画布中央，四周留透明背景。
```

### 后续帧（编辑已有图）

```
这是上一帧的生成结果。请保持图中角色所有细节完全不变——
发型、五官、服装颜色、猫耳形状、尾巴、身体比例全部不要动。

只做以下一处调整：[描述要改的唯一内容]

其他部分保持与上传图片完全一致。
```

### 如果 NB2 改得不对

```
不对，这次身体上移太多了。再来一次，上移幅度减少一半。
保持其他部分完全不变。
```

## 四、为什么 idle 没有呼吸起伏

你反馈 idle 只有尾巴和表情变化、身体没有上下起伏。以下是原因：

### 原因 1：独立帧 = 独立角色

如果你每帧都开新对话、新写一次完整 prompt，NB2 会将每帧视为**不同的角色**。结果是：
- 颜色有 ±5% 偏差
- 身体比例有变化
- 猫耳形状不一致
- "呼吸"的 1~2 像素起伏完全淹没在这些偏差里

### 原因 2：prompt 写的是"新画"不是"编辑"

```
之前写的（会被理解为新画）：
"猫娘正面全身像素画角色：身体前倾约5度，双肩向前..."

如果改成（编辑模式）：
"这是帧1。保持所有细节不变，只做：将身体垂直上移一点"
```

### 原因 3：呼吸在 64×64 里太微妙

1 像素的上下移动在 512×512 中只有 8 像素。NB2 对这种微小变动不敏感。

### 解决方案

要解决 idle 呼吸问题，**4 条缺一不可**：

| # | 规则 | 说明 |
|---|------|------|
| 1 | 同一对话连续发 | 利用 NB2 的上下文记忆 |
| 2 | 每帧上传上一帧 | 告诉 NB2"修改这张已有图" |
| 3 | 每帧只改 1 个参数 | 身体上移 OR 尾巴摆动，不要同时 |
| 4 | 如果 64×64 不行，试 128×128 | 1024px 空间里 8px 的位移更容易被模型理解 |

### 128×128 版本的优势

| 对比 | 64×64 版 | 128×128 版 |
|------|----------|------------|
| prompt 中写 | 在 512×512 画布中 | 在 1024×1024 画布中 |
| 1像素变化在生成空间里 | 8px | 8px（分辨率更高但缩放比一致）|
| 角色细节 | 比较有限 | 更丰富，轮廓更清晰 |
| 呼吸起伏感知难度 | 较难 | 较容易 |
| 最终精灵表 | 512×1344 | 1024×2688 |

## 五、推荐的实践流程

### 第 1 步：先验证 idle（4 帧）

在 Gemini 里新建一个对话，按以下顺序发 4 条消息。**先只做 idle，验证方法可行再继续。**

| 消息 | 操作 | prompt 要点 |
|------|------|------------|
| 1 | 上传角色参考图 | 完整描述首帧站姿（见逐帧指南）→ 下载 |
| 2 | 上传 idle_f1 | "保持所有不变，只做：身体垂直上移"→ 下载 |
| 3 | 上传 idle_f2 | "保持所有不变，只做：身体下移回地面"→ 下载 |
| 4 | 上传 idle_f3 | "回到第一帧的完全相同姿态"→ 下载 |

### 第 2 步：在 Aseprite 中检查

把生成的 4 帧拖进 Aseprite：
- 逐帧播放看身体是否有起伏
- 如果不连贯 → 回到 Gemini 对话中调整措辞重做某帧
- 如果帧间角色走形 → 新开对话，首帧上传参考图，重新开始

### 第 3 步：批量扩展

idle 验证成功后，每行动画新建**一个独立对话**，重复以上流程。

---

## 六、Aseprite 后处理步骤

1. 将下载的 PNG 用 rembg 去掉背景
2. 裁切到准确帧尺寸，缩放到最终尺寸（64×64 或 128×128）
3. 在 Aseprite 中对齐所有帧的 pivot 点（以脚底为参考）
4. 手动修正像素不一致的地方
5. 按行排列 → 导出 spritesheet
