### 2. 服务层 + 数据库

- **数据库**: SQLite 8张表 (Ghosts/ChatMessages/EmotionalEvents/ShortTermMemories/LongTermMemories/MasterImpressions/ConversationChunks/Experiences/AppState) + 完整CRUD
- **AI服务**: OpenAI 兼容协议统一接口 (chat/vision/image)，支持独立 vision_model 和 image_gen_endpoint
- **记忆服务**: 三层压缩框架 (本地即时→AI语义→经验提取) + 优先级加载
- **热键服务**: Ctrl+Alt+X 截图 + Ctrl+Alt+C 对话 (Pressed 状态检查)
- **截图服务**: Win32 API (GetDC/BitBlt/GetDIBits) + png crate，DPI感知，15秒超时
- **时间线服务**: 情感tick (60s) + 不活跃检测 (24h/72h) + 好奇心调度 (5min)
- **记忆压缩器**: STM→LTM 批量AI压缩 + 经验提取 + **AI辅助记忆模糊化 (P9)**
- **情感分析**: 对话后AI提取 event_type + love_hate_hint + 6维印象delta
- **注册的 Tauri 命令**: 28个

### 4. 关键决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 情感模型 | 方向敏感阻尼 + 可变基线 | v1 弹簧模型导致长期关系回归平淡 |
| 防复制 | 叙事性软约束 + 微扰 | DRM 伤害用户体验 |
| 记忆压缩 | 三层渐进 (本地→AI→情感) | 降低 API 成本 |
| 技术栈 | Tauri 2 + Vue 3 + Rust | Web 栈天然适合自由形状 UI |
| AI 接入 | OpenAI 兼容协议统一 | 90%+ 模型兼容此协议 |
| 截图 | Win32 API + png crate | DPI 感知、无外部进程依赖 |
| 窗口 | 320×720 透明无边框置顶 | 桌宠浮在桌面上 |
| TLS | rustls (非 native-tls) | 显式指定避免 HTTPS 请求失败 |
| Ghost 加密 | AES-256-GCM + HKDF-SHA256 | 每文件独立 salt+nonce，前向安全 |
| 对话交互 | 热键+点击 → 气泡浮层 | 比面板内输入更符合"桌面伙伴"定位 |
| 气泡风格 | 日系漫画风 (硬描边 + 三角尾巴) | 设计文档要求的风格 |
| 动画映射 | AnimationState 8种 → 策略模式 | 零代码改动即可切换渲染器 |
| 时间线服务 | timeline_tick 替代 tick_ghost | 统一情感tick + 不活跃 + 好奇心 |
| TTS | SpeechSynthesis (离线) + Edge TTS 规划 (在线) | 最低可用已就绪，待优化语音质量 |
| 人格 Prompt | 双层连续阈值 | 6维人格每维标签层+细节层，消除5档离散跳变 |
| 生图触发 | `[GENERATE_IMAGE:描述]` Prompt 标记 | AI 自主决定何时画图 |
| 情感事件应用 | 对话 AI 主导 / 非AI 硬编码 | 消除 Sensibility 3次冲击、Impression 2次冲击 (P8) |
| 记忆模糊 | 数值调整 + AI 文本模糊双机制 | 设计文档 §4.3 完整实现 (P9) |
| 窗口拖拽 | Tauri 2 `window.startDragging()` API | `data-tauri-drag-region` 在部分 Tauri 2 版本不支持；`-webkit-app-region: drag` 与点击交互冲突；手动 IPC `setPosition` 因通信延迟产生卡顿。`startDragging()` 使用 OS 原生拖拽，零 IPC 延迟。 |
| 回应模式 | 双模式 (Companion/Assistant) | 截图场景天然需要实用回答 vs 日常闲聊保留灵魂感 |
| 情绪动画分离 | 情绪=一次性反应 + 日常=行为池权重 | loveHate 不再锁定循环动画（"一直蹦"不自然）；情绪反应播完回 idle；loveHate 只调日常行为池概率 |
| 动画竞态 | animationGen 代数计数器 | 情绪反应与日常行为各自的 setTimeout 互相覆盖；代数检查使旧回调自动失效，类似游戏引擎版本号取消 |

### P19 — 动画状态机重构：情绪反应/日常行为池/animationGen 竞态修复 (2026-04-27) ✅

> **核心问题**：v2 设计中 `loveHate → MoodState → AnimationState` 的映射导致宠物动画被永久锁定在情绪状态上（如 loveHate > 50 时宠物一直循环"开心跳跃"），不符合"人类伙伴"的自然表现。同时情绪反应与日常行为的 `setTimeout` 存在竞态，互相覆盖动画状态。

#### 架构重构：情绪反应 vs 日常行为池分离

| 概念 | 旧设计 | 新设计 |
|------|--------|--------|
| `loveHate` 的作用 | 直接映射到动画状态（锁定） | 只控制日常行为池权重 |
| 基态动画 | 情绪决定（loveHate > 50 → 永远 happy） | 永远是 idle |
| 情绪表达 | 持续循环情绪动画 | 一次性反应动画，播完回 idle |
| 日常行为 | 在情绪动画上叠加 | 从 idle 出发，播完回 idle |

#### 代码改动

| # | 模块 | 改动 | 文件 | 说明 |
|---|------|------|------|------|
| 1 | 重命名 | `IdleAction` → `DailyBehavior` | `useAnimation.ts` | 6 组重命名：currentIdleAction→currentBehavior, isPerformingIdle→isPerformingBehavior, startIdleLoop→startDailyRoutine, stopIdleLoop→stopDailyRoutine, triggerIdleAction→triggerDailyBehavior, IDLE_ACTION_TO_ANIMATION_STATE→BEHAVIOR_TO_ANIMATION |
| 2 | updateMood 语义变更 | 不再设置 `currentAnimationState` | `useAnimation.ts` | 只更新 mood → 影响日常行为池权重，不锁动画 |
| 3 | 删除映射 | `MOOD_TO_ANIMATION_STATE` | `useAnimation.ts` | mood 不再直接锁定动画状态 |
| 4 | 基态回退统一 | `playOneShot`/`executeAction` 结束后回 `'idle'` | `useAnimation.ts` | 旧逻辑回退到 `MOOD_TO_ANIMATION_STATE[mood]`（可能不是 idle） |
| 5 | 新增情绪反应 | `playEmotionReaction()` + `EMOTION_REACTION_MAP` | `useAnimation.ts` | 11 种 eventType → {state, duration} 映射；未知类型按 loveHateHint 正负回退 happy/cold/content |
| 6 | animationGen 代数计数器 | 消除 setTimeout 竞态 | `useAnimation.ts` | `playOneShot` 和 `executeAction` 开始时 `++animationGen`，7 处异步回调检查代数匹配才回退；旧动画的回调自动失效 |
| 7 | playOneShot 增强 | 行为锁 + 暂停/恢复日常调度 | `useAnimation.ts` | 开始: `isPerformingBehavior=true` + `stopDailyRoutine()`；回调: 代数检查→回idle+解锁，无论如何 `startDailyRoutine()` |
| 8 | chat:post-processed 改造 | 调用 `playEmotionReaction` | `App.vue` | `updateMood` 只更新权重，`playEmotionReaction` 播一次性情绪动画 |
| 9 | 导入名更新 | 6 组重命名同步 | `App.vue` | startDailyRoutine/stopDailyRoutine/playEmotionReaction 等 |
| 10 | 技术设计文档 | v2.1 → v2.2 | `技术设计文档_v2.md` | 新增 8.4 节完整记录架构设计 + animationGen 机制 + 代码落地位置 |

#### animationGen 竞态修复原理

```
t=0    日常行为 bounce → gen=1, 设800ms后回idle
t=400  情绪反应 happy → gen=2, 旧gen=1失效
t=800  bounce 的回调 → gen=1 ≠ animationGen=2 → 跳过 ✓
t=1900 happy 的回调 → gen=2 === animationGen=2 → 回idle ✓
```

#### 效果对比

| 场景 | 修复前 | 修复后 |
|------|--------|--------|
| 对话后感到开心 | loveHate>50 → 动画永锁 happy | 播一次 happy 跳跃 → 回 idle |
| 对话后不高兴 | loveHate<-50 → 动画永锁 distant | 播一次 cold/distant → 回 idle |
| 日常空闲 | 被情绪锁定的循环动画 | idle 弹跳 + 行为池随机穿插 |
| 情绪反应被日常打断 | setTimeout 覆盖动画状态 | 代数检查，旧回调自动失效 |
| 日常行为被情绪打断 | 动画状态混乱 | `++animationGen` 使旧行为失效，新动画接管 |

| UserCaredAboutPet / UserSharedPersonalStory / NormalChat | content | 800~1200ms |
| UserGotAngry | cold | 1500ms |
| UserDismissedPet / UserIgnoredPet | distant | 1200~1500ms |
| CuriosityTriggered | curious | 800ms |
| (未知类型, hint>1) | happy | 1200ms |

### P18 — 拖拽修复 + DPI 缩放适配 + hover 圆角恢复 + 窗口最小宽度 (2026-04-26) ✅

> **根源复盘**：拖拽功能从 P17 的占位实现改为真实交互后，经历三次问题——① 完全拖不动（缺少 `core:window:allow-set-position` 权限）；② 拖拽偏移（`screenX/Y` 与 `outerPosition()` 单位不一致导致的 DPI 缩放问题）；③ 拖拽卡顿（手动 `mousemove` → IPC `setPosition` 每像素发一次 js→rust 通信）。最终方案使用 Tauri 2 原生 `startDragging()` API，OS 底层零延迟拖拽。

| 2 | DPI 缩放修复 | `e.screenX/Y` CSS 像素 × `devicePixelRatio` → 物理像素 | `App.vue` | `outerPosition()` 返回物理像素，`screenX/Y` 返回逻辑像素，高 DPI 下直接加减导致鼠标和窗口偏移 |
| 3 | 原生拖拽 | 弃用 `mousemove` + `setPosition` IPC 手动拖拽，改用 `win.startDragging()` | `App.vue` | OS 原生拖拽，零 IPC 延迟，与设置窗口一致流畅；同步调用确保事件上下文不丢失 |
| 4 | 点击/拖拽分离 | `onPetMouseDown` 记录窗口位，拖拽结束比较 `didDrag` | `App.vue` | 区分点击开聊天和拖拽移窗口，`handlePetClick` 检查 `didDrag` 抑制误触 |

#### 拖拽方案演进

| 方案 | 问题 | 结论 |
|------|------|------|
| `data-tauri-drag-region` 属性 | 部分 Tauri 2 版本不支持或事件被其他元素拦截 | 弃用 |
| CSS `-webkit-app-region: drag` | 与点击开聊天交互冲突（drag region 消耗 mousedown） | 弃用 |
| 手动 `mousemove` + `setPosition` | IPC 每像素通信卡顿 + DPI 缩放偏移 + 权限问题 | 弃用 |
| `win.startDragging()` API | 同步调用，OS 原生零延迟，无 DPI 问题 | ✅ 采用 |

> 修复 Edge TTS 无法使用的问题（微软 2024 年末更新 DRM 协议导致 403），同时修复 TTS 引擎在主窗口/设置窗口之间切换失效的事件通信 Bug。

| # | 模块 | 改动 | 文件 | 说明 |
|---|------|------|------|------|
| 1 | TTS 引擎切换 | 删除失效的 CustomEvent + 修复 Tauri 事件 await | `Settings.vue` / `App.vue` | CustomEvent 发在 Settings 自己的 window 对象上，主窗口永远收不到；删除该通道，统一用 Tauri IPC 事件（加 `await` 确保注册完成） |
| 2 | Edge TTS 协议 | HTTP→WebSocket→crate 切换 | `tts_service.rs` / `Cargo.toml` | 手动实现 3 次（HTTP POST / WebSocket / WebSocket+DRM）均失败；最终切换到 `edge-tts-rust` crate 处理所有协议细节（`Sec-MS-GEC` SHA256 动态令牌、`ConnectionId`、`Origin: chrome-extension://`、二进制音频 2 字节头部剥离） |

- **TTS 切换失效**：Settings 窗口用 `window.dispatchEvent(CustomEvent)` 发到自己的 window 对象，主窗口 `window.addEventListener` 收不到（两个 WebviewWindow 各有独立的 `window`）；加上 `listen('tts-updated')` 没加 `await`，监听器可能还没注册完事件就来了。
